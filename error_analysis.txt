ROOT CAUSE ANALYSIS: WHY JSX ERRORS KEEP HAPPENING
AND HOW TO FIX THEM PERMANENTLY
====================================================


1. WHAT ERRORS HAVE BEEN OCCURRING
-----------------------------------------------------
All errors have been the SAME class of bug:
  [PARSE_ERROR] Expected , or ) but found {
  [PARSE_ERROR] Unexpected token. Did you mean {'}'} or &rbrace;?

These are JSX structure errors — mismatched or duplicate opening/closing tags.

Files affected so far:
  - CatalogueGenerator.tsx (line 230) — extra orphaned closing div
  - BusinessProfile.tsx   (line 123) — two component trees accidentally merged


2. ROOT CAUSE (WHY IT KEEPS HAPPENING)
-----------------------------------------------------
The eplace_file_content tool (partial replacement) is the culprit.

When I use it on JSX files:
  - The tool finds a target block inside the file and replaces it.
  - If the target is slightly off, the new code gets INJECTED into the 
    middle of existing code rather than replacing it.
  - This leaves the old closing tags AND the new closing tags both present.
  - Result: mismatched braces ? Vite parse error ? red screen.

The tool even warned each time:
  "You had inaccuracies in your replacement chunks..."
But I proceeded anyway. That was the mistake.


3. PERMANENT SOLUTION
-----------------------------------------------------
RULE 1: For JSX files (any .tsx with complex structure), 
        ALWAYS use full file rewrite (write_to_file with Overwrite=true).
        NEVER use partial replace on nested JSX.

RULE 2: Partial replacements are only safe for:
        - Backend .ts files (no JSX)
        - CSS files
        - Config files  
        - Truly single-line changes

RULE 3: After EVERY file change, run:
        npx tsc --noEmit
        and confirm exit code 0 before moving to the next file.
